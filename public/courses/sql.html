Chapitre 01 · Fondamentaux

SELECT, WHERE & Bases du SQL

Tout commence par SELECT. Mais un professionnel sait filtrer, trier, limiter et alias avec précision. Voici les fondations qui portent tout le reste.

La requête SELECT anatomy

Chaque clause a un rôle précis et s'exécute dans un ordre interne strict (différent de l'ordre d'écriture) :

SQL — Anatomie
-- Ordre d'ÉCRITURE (syntaxe)
SELECT   nom, montant, statut                 -- 5. Ce qu'on retourne
FROM     COMMANDES                             -- 1. Source de données
WHERE    montant > 50000                       -- 2. Filtrage lignes
GROUP BY statut                              -- 3. Regroupement
HAVING   COUNT(*) > 5                       -- 4. Filtre sur groupes
ORDER BY montant DESC                          -- 6. Tri
LIMIT    10;                                 -- 7. Limitation
💡 Astuce

L'ordre d'exécution est : FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. C'est pourquoi on ne peut pas utiliser un alias de SELECT dans un WHERE.

Filtres WHERE

WHERE supporte tous les opérateurs de comparaison et logiques. Voici les patterns les plus utiles en analyse de données :

SQL — Filtres avancés
-- Comparaisons
WHERE montant >= 100000 AND statut = 'ACTIF'

-- Plage de valeurs
WHERE date_inscription BETWEEN '2024-01-01' AND '2024-12-31'

-- Liste de valeurs
WHERE produit IN ('VIE', 'AUTO', 'SANTE')

-- Pattern matching
WHERE nom LIKE 'Ama%'        -- commence par "Ama"
WHERE nom LIKE '%KOFFI%'    -- contient "KOFFI"
WHERE code LIKE 'CI___'     -- CI + exactement 3 chars

-- Valeurs nulles
WHERE date_resiliation IS NULL       -- commande encore active
WHERE telephone IS NOT NULL          -- client joignable

-- Négation
WHERE statut NOT IN ('RESILIE', 'EXPIRE')

Aliases & DISTINCT

SQL
-- Alias de colonnes (AS facultatif)
SELECT
  commande_id                               AS id,
  montant / 1000                            AS montant_k,
  UPPER(nom)                               nom_maj,
  DATEDIFF(DAY, date_inscription, GETDATE()) AS anciennete_jours
FROM COMMANDES;

-- DISTINCT : valeurs uniques
SELECT DISTINCT produit FROM COMMANDES;         -- liste des produits
SELECT DISTINCT agence, ville FROM CLIENTS;   -- combinaisons uniques

-- Alias de table (essentiel pour les jointures)
SELECT p.commande_id, c.nom
FROM   COMMANDES p
JOIN   CLIENTS c ON p.client_id = c.client_id;

CASE WHEN — Colonne calculée conditionnelle

SQL — CASE WHEN
SELECT
  commande_id,
  montant,
  CASE
    WHEN montant < 50000  THEN 'Petite commande'
    WHEN montant < 200000 THEN 'Commande standard'
    ELSE                      'Grande commande'
  END AS categorie_montant
FROM COMMANDES
WHERE statut = 'ACTIF';

📅
Dates
GETDATE(), DATEDIFF(), DATEADD(), YEAR(), MONTH(), DAY(), FORMAT()
📝
Chaînes
UPPER(), LOWER(), TRIM(), LTRIM(), RTRIM(), LEN(), SUBSTRING(), CHARINDEX(), CONCAT()

Nombres
ROUND(), FLOOR(), CEILING(), ABS(), CAST(), CONVERT(), ISNULL() / COALESCE()

NULL n'est pas égal à NULL. WHERE colonne = NULL ne retourne rien. Utilisez toujours IS NULL ou IS NOT NULL.

Chapitre 02 · Fondamentaux

Jointures SQL

Les jointures sont le cœur du SQL relationnel. Bien les maîtriser, c'est ne plus jamais avoir de données manquantes ou dupliquées inexpliquées.

Les 5 types de JOIN visualisés

INNER JOIN
Seulement les lignes qui ont une correspondance dans les deux tables
LEFT JOIN
Toutes les lignes de gauche + correspondances de droite (NULL si absent)
RIGHT JOIN
Toutes les lignes de droite + correspondances de gauche (NULL si absent)
FULL OUTER JOIN
Toutes les lignes des deux tables, NULL là où pas de correspondance
CROSS JOIN
Produit cartésien : chaque ligne de A avec chaque ligne de B (N×M lignes)
SELF JOIN
Une table jointe à elle-même — hiérarchies, comparaisons intra-table

Exemples concrets — Base finance

SQL — INNER JOIN
-- Commandes avec infos clients (seulement les commandes qui ont un client)
SELECT
  p.commande_id,
  c.nom             AS client,
  c.ville,
  p.produit,
  p.montant,
  p.statut
FROM        COMMANDES  p
INNER JOIN CLIENTS  c  ON p.client_id = c.client_id
WHERE p.statut = 'ACTIF'
ORDER BY p.montant DESC;
SQL — LEFT JOIN (clients sans commande)
-- TOUS les clients, même ceux sans commande (prospect non converti)
SELECT
  c.client_id,
  c.nom,
  c.ville,
  ISNULL(p.produit, 'AUCUNE')   AS produit,
  ISNULL(p.montant, 0)            AS montant
FROM       CLIENTS  c
LEFT JOIN COMMANDES  p  ON c.client_id = p.client_id
ORDER BY montant DESC;
SQL — Jointure multiple (3 tables)
-- Transactions avec info commande ET client
SELECT
  s.transaction_id,
  c.nom             AS client,
  p.produit,
  s.montant,
  s.date_transaction,
  s.statut          AS statut_transaction
FROM        TRANSACTIONS s
INNER JOIN COMMANDES   p  ON s.commande_id  = p.commande_id
INNER JOIN CLIENTS   c  ON p.client_id  = c.client_id
WHERE s.statut = 'EN_COURS'
ORDER BY s.montant DESC;
🚨 Pièges classiques des jointures

Explosion de lignes : si la relation n'est pas 1-N stricte, un JOIN peut multiplier les lignes. Toujours vérifier le COUNT(*) avant et après. NULL dans la clé : NULL = NULL est FAUX en SQL — une ligne avec NULL comme clé étrangère ne joindra jamais.

Chapitre 03 · Intermédiaire

Agrégations & GROUP BY

GROUP BY transforme des milliers de lignes en résumés décisionnels. Maîtrisez HAVING, les fonctions d'agrégation conditionnelle et ROLLUP pour des rapports multidimensionnels.

Fonctions d'agrégation essentielles

SQL — Agrégations
SELECT
  produit,
  COUNT(*)                              AS nb_commandes,
  COUNT(DISTINCT client_id)             AS nb_clients_uniques,
  SUM(montant)                             AS total_montants,
  AVG(montant)                             AS montant_moyenne,
  MIN(montant)                             AS montant_min,
  MAX(montant)                             AS montant_max,
  STDEV(montant)                           AS ecart_type,
  -- Agrégation conditionnelle (SUM/COUNT avec CASE)
  SUM(CASE WHEN statut='ACTIF' THEN montant ELSE 0 END) AS ca_actif,
  COUNT(CASE WHEN statut='RESILIE' THEN 1 END)   AS nb_resilies
FROM COMMANDES
GROUP BY produit
ORDER BY total_montants DESC;

WHERE vs HAVING

💡 Règle d'or

WHERE filtre les lignes AVANT l'agrégation. HAVING filtre les groupes APRÈS l'agrégation. On ne peut pas utiliser une fonction d'agrégation dans un WHERE.

SQL — WHERE vs HAVING
-- WHERE filtre les lignes avant GROUP BY
SELECT agence, SUM(montant) AS ca
FROM   COMMANDES
WHERE  statut = 'ACTIF'          -- avant agrégation ✅
GROUP BY agence;

-- HAVING filtre les groupes après GROUP BY
SELECT agence, SUM(montant) AS ca
FROM   COMMANDES
WHERE  statut = 'ACTIF'
GROUP BY agence
HAVING SUM(montant) > 500000;    -- seulement agences > 500K ✅

-- ERREUR : COUNT dans WHERE
-- WHERE COUNT(*) > 5 ← INTERDIT !

ROLLUP — Sous-totaux automatiques

SQL — GROUP BY ROLLUP
SELECT
  ISNULL(produit,  'TOUS PRODUITS')  AS produit,
  ISNULL(agence,   'TOUTES AGENCES') AS agence,
  SUM(montant)                           AS ca_total,
  COUNT(*)                             AS nb_commandes
FROM   COMMANDES
WHERE  statut = 'ACTIF'
GROUP BY ROLLUP(produit, agence)
ORDER BY produit, agence;
Chapitre 04 · Intermédiaire

Sous-requêtes & CTEs

Les sous-requêtes et CTEs permettent de décomposer des problèmes complexes en étapes lisibles. Les CTEs (Common Table Expressions) sont la clé d'un SQL maintenable.

Sous-requêtes scalaires et dans FROM

SQL — Sous-requêtes
-- Scalaire : retourne une valeur unique
SELECT commande_id, montant,
  montant - (SELECT AVG(montant) FROM COMMANDES) AS ecart_moyenne
FROM COMMANDES;

-- Dans le FROM (table dérivée)
SELECT produit, ca_produit,
  ca_produit * 100.0 / ca_total AS part_pct
FROM (
  SELECT produit, SUM(montant) AS ca_produit
  FROM   COMMANDES
  GROUP BY produit
) sub_produits
CROSS JOIN (
  SELECT SUM(montant) AS ca_total FROM COMMANDES
) sub_total
ORDER BY part_pct DESC;

EXISTS vs IN — Performances

SQL — EXISTS
-- Clients qui ont AU MOINS un transaction en cours
SELECT c.client_id, c.nom
FROM   CLIENTS c
WHERE EXISTS (
  SELECT 1
  FROM   TRANSACTIONS s
  JOIN   COMMANDES   p ON s.commande_id = p.commande_id
  WHERE  p.client_id = c.client_id
  AND    s.statut = 'EN_COURS'
);

-- NOT EXISTS : clients sans aucun transaction
SELECT c.client_id, c.nom
FROM   CLIENTS c
WHERE NOT EXISTS (
  SELECT 1 FROM TRANSACTIONS s
  JOIN   COMMANDES p ON s.commande_id = p.commande_id
  WHERE  p.client_id = c.client_id
);

CTEs avec WITH — La clé du SQL lisible

SQL — CTE (Common Table Expression)
-- Exemple : clients à risque (taux de perte > 80%)
WITH
montants_par_client AS (
  SELECT p.client_id, SUM(p.montant) AS total_montants
  FROM   COMMANDES p
  WHERE  p.statut = 'ACTIF'
  GROUP BY p.client_id
),
transactions_par_client AS (
  SELECT p.client_id, SUM(s.montant) AS total_transactions
  FROM   TRANSACTIONS  s
  JOIN   COMMANDES    p ON s.commande_id = p.commande_id
  GROUP BY p.client_id
),
taux_retour AS (
  SELECT
    pc.client_id,
    pc.total_montants,
    ISNULL(sc.total_transactions, 0)   AS total_transactions,
    ISNULL(sc.total_transactions, 0) * 100.0
      / NULLIF(pc.total_montants, 0)    AS taux_pct
  FROM       montants_par_client    pc
  LEFT JOIN transactions_par_client sc ON pc.client_id = sc.client_id
)
SELECT
  ts.client_id, c.nom,
  ts.taux_pct,
  CASE WHEN ts.taux_pct > 80 THEN '🔴 Risque élevé'
       WHEN ts.taux_pct > 50 THEN '🟡 Risque modéré'
       ELSE                        '🟢 Risque faible'
  END AS niveau_risque
FROM       taux_retour ts
INNER JOIN CLIENTS            c  ON ts.client_id = c.client_id
ORDER BY ts.taux_pct DESC;
Chapitre 05 · Avancé

Fonctions Fenêtre (Window Functions)

Les fonctions fenêtre (OVER / PARTITION BY) sont la fonctionnalité la plus puissante de SQL avancé. Elles permettent des calculs par groupe SANS GROUP BY — chaque ligne conserve ses détails tout en accédant aux agrégats de son groupe.

Anatomie d'une fonction fenêtre

SQL — Syntaxe OVER
FONCTION() OVER (
  PARTITION BY colonne_groupe    -- définit la "fenêtre"
  ORDER BY     colonne_tri       -- ordre dans la fenêtre
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)

ROW_NUMBER, RANK, DENSE_RANK

SQL — Numérotation
SELECT
  commande_id, produit, montant,
  ROW_NUMBER()   OVER(PARTITION BY produit ORDER BY montant DESC) AS rn,
  RANK()         OVER(PARTITION BY produit ORDER BY montant DESC) AS rnk,
  DENSE_RANK()   OVER(PARTITION BY produit ORDER BY montant DESC) AS drnk,
  NTILE(4)       OVER(PARTITION BY produit ORDER BY montant DESC) AS quartile
FROM COMMANDES
WHERE statut = 'ACTIF';

LAG & LEAD — Accès aux lignes voisines

SQL — LAG / LEAD
-- Évolution mensuelle du CA
SELECT
  mois,
  ca_mensuel,
  LAG(ca_mensuel, 1, 0) OVER(ORDER BY mois) AS ca_mois_prec,
  ca_mensuel - LAG(ca_mensuel) OVER(ORDER BY mois) AS variation,
  LEAD(ca_mensuel) OVER(ORDER BY mois)            AS ca_mois_suiv,
  -- Cumul progressif
  SUM(ca_mensuel) OVER(ORDER BY mois
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS ca_cumul,
  -- Moyenne glissante sur 3 mois
  AVG(ca_mensuel) OVER(ORDER BY mois
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)       AS moy_glissante_3m
FROM CA_MENSUEL;

Cas pratique — Top 3 commandes par agence

SQL — Filtre sur rang
WITH ranked AS (
  SELECT
    agence, commande_id, client_id, montant,
    ROW_NUMBER() OVER(
      PARTITION BY agence
      ORDER BY     montant DESC
    ) AS rang
  FROM COMMANDES
  WHERE statut = 'ACTIF'
)
SELECT agence, commande_id, montant, rang
FROM   ranked
WHERE  rang <= 3  -- 3 meilleures commandes par agence
ORDER BY agence, rang;
💡 Conseil expert

On ne peut pas filtrer directement sur un alias de fonction fenêtre dans le WHERE (ordre d'exécution). Il faut toujours envelopper dans une CTE ou sous-requête, puis filtrer dans le SELECT externe.
